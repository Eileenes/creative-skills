# 头像立体化

以本次用户提供的图片为角色依据。支持不同用户、人物与非人物头像，不内置任何人的长相或私人照片。完成一次可直接使用的头像制作，而不只交付提示词。

## 输入与视觉方向

- 先实际查看参考图，提取必须保留的脸型、五官比例、发型、眼镜、衣服、配色及标志性细节；多人图且主角不明确时才询问主角。
- 默认沿用原画设计增强体积光影；明确要求软陶、公仔、3D卡通或参考某张风格图时遵循用户要求。不要自动改变年龄、肤色、体型或变成大头婴儿。
- 让用户原图决定身份，风格图只决定材质与光影。已满意的成品可作为后续风格锚点，原始身份参考仍保留。
- 运用柔和主光、适度轮廓光、自然接触阴影和可读材质制造体积感，避免强塑料油光、黑边和过度磨皮。
- 背景简洁、人物与背景明度分离；默认正面或轻微转角、头肩构图。发顶和两侧留安全距离，脸部在小尺寸下清晰。出框、圆框、文字和额外道具只在用户要求时添加。

## 连续修改与配饰

- 用户说“改成”“加一个”时，以上一版明确指向的成品为编辑目标，继承该版尺寸、背景和已接受的修改；不要从原图重做而撤销中间修改。若最新候选被否定，回到最近接受的版本。
- 把本次“只改什么”和“保留什么”写入提示词。徽章、衣服图案等局部修改保持位置、材质、透视和光照；不要承诺生成式编辑能使其他像素完全不变。
- 左右默认指画面观看者的左右，并在开始时用一句话说明；用户明确说人物左手/左肩则按人物方向处理。
- 肩部饰物应有接触阴影和支撑关系，风格与角色一致，不能遮脸、眼镜或已有重要徽章。主体仍占主要面积，配饰在小图里可读，避免靠边被平台裁切。
- 数量和排列属于验收条件。例如九筒是三行三列共九个圆点，不是数字“9”；应放大查看局部并计数，不能仅凭提示词确认成功。
- 一次只修复明确问题。连续两次针对性修正仍不满足关键要求时，展示差异和当前限制，请用户选择继续方向，避免无止境重绘。
- 保存一个简短的本地版本记录：原始参考图、当前编辑底图、用户本轮要求、必须保留项、目标尺寸、实际输出路径及是否得到用户确认。生成成功不等于用户已接受；更换用户/角色时新建记录。

## 尺寸是交付约束

优先级：用户明确的宽高像素 > 用户比例与用途 > 用途预设。

- 支持 `640×640`、`800x800`、`宽900高1200` 等表达，记录最终 `width`、`height`，单位默认像素。
- 仅给比例时先按比例构图并选合理像素尺寸，明确告诉用户；不能把 `1:1` 当作像素尺寸。
- 微信头像未指定尺寸时采用 **640×640、1:1、实色背景 PNG**；通用头像默认1024×1024。均为本技能的交付预设，不宣称是平台唯一或官方强制规格。
- 显式自定义尺寸覆盖预设，即使是非方形。若用于方形头像，说明平台可能裁切，并将脸部放在中央安全区；不要擅自丢弃指定尺寸。
- 用户明确要求透明时保留真实alpha。不要默认把平台显示蒙版（圆形或圆角）烘焙进上传图。
- 生图尺寸与最终文件尺寸分开处理：尽量先生成相同比例、足够清晰的母版，读取实际尺寸后再做精确导出。不要声称提示词里的像素数就是文件实测尺寸。
- 大图导出需考虑内存和原图清晰度；放大像素不等于增加细节。不支持的尺寸如实说明，并选择更高分辨率生成或明确的重采样方案。

## 生成与导出

1. 用简短说明固定本次身份特征、风格、背景及目标尺寸，信息充分就开始。
2. 使用可用的图像生成/编辑工具并附参考图，不用代码绘制替代人物图。Codex 中优先内置 image_gen；先查看本地参考图，透明输出时设置真正透明背景。若无生图能力，明确只完成提示词，不假称已生成。不要自动注册外部服务或切换付费API。
3. 提示词包含：各参考图角色、保留特征、变化范围、构图、光照材质、背景、比例、禁用额外文字/角色。保存本次提示词以便复用。
4. 只取工具实际返回的本次产物，保留母版；生成结果属于当前项目时另存项目目录，不覆盖原图。
5. 用户要求精确像素时，使用下方脚本（需Pillow）进行尺寸导出。相同比例使用等比缩放；不同比例默认留边，不拉伸人物；只有构图允许或用户要求时才裁切。背景去除、补画和视觉修复交给图像工具。

```bash
python3 scripts/export_avatar.py INPUT OUTPUT --width 640 --height 640
python3 scripts/export_avatar.py INPUT OUTPUT --width 900 --height 1200 --fit contain --background '#fff6eb'
```

以上脚本路径相对于技能目录，实际调用需解析为绝对路径，不能假设用户工作目录就是技能目录。依赖见 requirements.txt。

脚本输出实际宽高、格式、透明信息和是否放大。默认禁止覆盖；默认背景 auto 在 PNG 导出时保留来源透明度，否则使用米白底。微信实色背景导出时显式传 `--background '#fff6eb'`。`--fit cover` 中央裁切，使用后必须确认未裁掉脸和发顶；`--background transparent` 保留或添加透明留边，不能去除原图背景；`--allow-upscale` 才允许超出源图的有效分辨率。

## 验收与交付

- 查看成品和64×64左右缩略图：仍像同一个角色，眼镜和五官完整、脸部易辨认，边缘无白边/假透明棋盘格。
- 实测输出宽高、格式、alpha；非方形和透明素材尤其要检查。发现身份漂移时针对该问题修改，不以“百分百保留”代替检查。
- 交付成品预览、下载路径、实测尺寸与调用示例；将用户照片与成品放在项目素材目录，不放进可分享技能包。

调用示例：
- “用 $avatar-depth 把这张图做成微信头像，保留原来的样子。”
- “用 $avatar-depth 做软陶风头像，800×800，米白背景。”
- “用 $avatar-depth 输出900×1200透明头像，别裁掉头发。”
- “把徽章换成九筒，其他沿用上一版。”
- “画面左肩加熊猫啃竹子，右肩加迷你火锅，保留徽章和640×640尺寸。”
