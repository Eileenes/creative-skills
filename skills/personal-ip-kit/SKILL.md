# 角色 IP 创建与内容复用

同一套流程服务不同用户，身份来自各自的参考图与角色档案，技能本身不预设人物、服装、配色或品牌。技能编排可用工具，不训练模型，不保证生成图逐像素一致，也不会因安装本技能自动获得生图或视频服务。

## 选择本次角色与模式

先区分用户要新建角色、修改已有角色，还是用已有角色创作内容。新上传的图片可能是人物参考、文章截图、场景参考或编辑目标；按用户描述判断，不把每张上传图片都当成新的身份。

角色选择顺序：用户明确给出的档案路径或角色名 → 本轮已明确的角色 → 当前项目 `.ip-characters/index.json` 的默认角色 → 仅有的一个角色。有多个候选且无法确定时，问一次角色选择；不要选“最新修改”的那个，不扫描其他项目寻找私人照片。具体档案格式与规则见 [角色档案](references/characters.md)。

首次查看实际参考图，后续新场景仍把原始身份图和当前主设定板实际传给生图工具。参考缺失时说明具体缺少哪张，不能宣称仅凭文字重建的结果就是同一 IP。只有原图、尚无主板时先生成主板。

按本次目标读取一个相关流程；只有跨模式任务才继续读其他文件：
- 创建或升级整套 IP：读 [创建流程](references/create.md)。
- Banner、单图、文章配图、视频素材：读 [内容应用](references/content.md)。
- 输出离线素材库和 ZIP：读 [打包规则](references/packaging.md)。

## 共用工作原则

用户明确要求优先于历史规范。固定外观的改变建立新版本，同步主板与档案，再扩展；不要悄悄覆盖用户已采用的标准。

优先复用已验收的透明素材。需要新姿势或场景时，提示词由“档案中的身份与风格 + 一个核心动作和对象 + 构图与留白 + 背景、文字要求”组成。不要拿上一张派生图无休止地继续派生。

使用环境内置生图工具；工具存在本地图片输入时传实际路径，只有会话图片输入时按该工具规范提供参考。透明素材要求真实 alpha。每项独立素材单独生成；主设定板可多视图，不能把一张九宫格充作多个独立文件。工具不可用时保留方案与提示词，如实说明未生成，不擅自转入付费 API 或上传第三方服务。

长标题、准确数据、图表关系和真实界面与角色画面分层制作。可用 SVG/HTML 等排版层组合生成图和可编辑文字，保留原图。不要用想象的界面充当操作教程截图。

默认只补问会影响身份或本次产物的缺失信息。用户已给清楚用途就开工；用户说“先做一套看看”时，可选择符合其定位的演示主题，但标明这是设计建议而非用户提供的正式文章。

## 验收与交付

查看每张新图：主体仍可辨认、固定结构一致、动作能解释内容；人物另查眼镜、手与肢体，动物或物品按其结构检查。核对文字、留白、画幅、边缘及真实透明通道。程序检查不能代替视觉检查。

发现问题优先局部修复；同一素材修复两轮仍有明显问题，说明剩余问题并交付可用替代姿势，不无限重试。图片动画、生成式视频、真正三维模型要分别命名。

保存到用户指定目录，或项目 `ip-output/<角色ID>/<日期>-<主题>-v1/`，同名递增，不覆盖旧版。保存独立图片、实际提示词、实际参考、可编辑排版（若制作）和验收记录。整套任务另交离线预览页与 ZIP。交付说明区分新生成、既有复用与排版衍生文件；只有实际执行的验证才能声称通过。

角色原图和个人档案放在用户工作区，不写进技能源目录。分享技能不需要分享角色照片；只有明确请求导出角色包时，才按清单打包其参考。公开发布另按用户指定范围执行。
