# 平台适配与时间设计

## 用目标选择路径

这些是可组合的结构，不是强制流程：

- **头像 → 角色 → 主页 → 目标动作**：适合短片和已经明确账号的观众。
- **入口 → 搜索 → 结果行 → 主页**：适合强调如何找到账号；长 ID 输入会消耗时间，可按词组分组呈现。
- **代表作品 → 作者身份 → 更多作品 → 访问／关注**：适合以内容价值吸引观众。
- **频道 → 内容栏目 → 订阅**：适合较长介绍，不必模拟每个浏览器操作。
- **价值短句 → 账号／有效二维码 → 留屏**：适合需要扫码进入的渠道；必须核对目的地。

核对每个平台实际存在的导航、搜索、主页头部、资料区、按钮、统计字段、封面和内容网格。不要为所有平台强行添加“横幅”“认证 ✓”或“Follow”。区分本人管理页面和访客页面：本人截图可以作为资料来源，但不能凭此声称该截图已经包含访客关注按钮。

无法确认最新 UI 时，可根据用户素材制作明确的宣传概念界面，准确保留身份信息；不要称其为当前产品的精确还原。确认平台页面时优先官方／用户提供资料，涉及本次实际网页或最新行为再查证。

## 角色驱动交互

| 角色 | 可用动作语言 | 界面反馈 |
| --- | --- | --- |
| 人物 | 伸手、按压、推开、拖动、轻跳 | 接触位置压下、卡片跟随手部、释放后回弹 |
| 四足动物 | 拍爪、鼻尖碰触、尾巴扫过、蹲起 | 按钮响应、标签展开、文字出现 |
| 鱼或漂浮角色 | 触碰、摆尾、俯冲、翻转 | 涟漪、按钮压下、面板沿运动方向展开 |
| 机器人 | 指向、吸附、伸缩、投射 | 卡片被带出、内容依次点亮 |
| 球或抽象形态 | 滚动、挤压、弹跳、分裂重组 | 凹陷、路径点亮、容器变形 |
| 无角色 | 光标、手势标记、卡片本体 | 点击反馈与连续布局变化 |

按角色能力选择动作，不机械复用鲸鱼摆尾、喷水和跳跃。若用户指定“跳一下打两个字符”，保留；否则优先有节奏的可读输入，账号最终字符必须正确。

角色从头像出现时，保留头像外框／卡片作为空间锚点，让角色由平面轮廓过渡到立体、跨过边缘落到表面。角色落点与面板位置关联，面板缩放或移动后仍要落在正确位置。搜索结果变主页时可沿用同一头像和资料容器，扩大后逐层展开内容。

## 时间预算

按以下优先级分配，不按旧案例百分比机械缩放：

1. 用户锁定的时段、音频长度、平台交付限制。
2. 身份与核心价值的阅读，以及片尾目标入口的停留。
3. 必须表达的动作与界面响应。
4. 出场、移动、镜头衔接及装饰。

8–12 秒通常需要压缩为出场、核心价值和一次 CTA；20–30 秒可容纳发现账号与资料展示；更长版本可增加代表内容。这些只是编排参考，不是允许范围。太短的要求应先精简步骤和文字；锁定要求互相冲突时说明具体冲突并询问取舍，不擅改总时长。

静止 1 秒不代表整段简介必然读得完。按实际字号、字数、语言和观看设备判断；必要时用用户可接受的精简价值句，保留原始简介供核对。最后一帧应足够稳定，让账号或二维码能被辨认。

## 节拍分配工具

`scripts/plan_timeline.py` 将正时长与帧率转换成连续、无缝、右端不包含的帧区间。它负责整数帧分配，不负责判断故事质量、文字能否读完、画面是否连续，也不是渲染器。

准备 JSON：

```json
{
  "duration_seconds": 15,
  "fps": 30,
  "beats": [
    {"id": "arrival", "weight": 2, "min_seconds": 1.2, "carry": "同一角色"},
    {"id": "profile", "weight": 3, "min_seconds": 2, "carry": "头像与资料容器"},
    {"id": "read", "kind": "hold", "fixed_seconds": 1.2, "carry": "完整资料"},
    {"id": "action", "weight": 2, "min_seconds": 1.4, "carry": "目标按钮"},
    {"id": "outro", "kind": "hold", "weight": 1, "min_seconds": 1, "max_seconds": 2, "carry": "片尾账号"}
  ]
}
```

从技能目录运行，或者使用脚本的绝对路径：

```bash
python3 scripts/plan_timeline.py brief.json --out timeline.json
```

- `duration_seconds`、`fps` 必须为正数；帧率也可写成 `"30000/1001"`。工具适用于不同总时长，不要求 19 秒。
- `beats` 非空，`id` 非空且唯一。每拍至少 1 帧，不自动删除节拍。
- `fixed_seconds` 锁定该拍长度；`min_seconds` 设置下限，`max_seconds` 设置上限。
- 其余时长按 `weight` 分配，默认 1；0 表示只保留下限。约束无法容纳整片时返回错误，不偷偷突破或丢弃要求。
- 总时长与固定时长取最近整帧，半帧向上；下限向上、上限向下取整。结果包含请求与实际时长及量化提示。需要严格总秒数时选择与 fps 相容的帧数；不能声称不可整除的时长仍精确等于请求值。
- `fixed_seconds` 固定长度，不是绝对开始时间。精确时间点要求应由代理换算成相邻区间，再验证所有关键点；工具不会编排重叠事件或自动对齐旁白。
- `carry`、`kind`、`action`、`camera` 等自定义字段保留。生成结果须补充或核对信息、动作、反馈、声音与镜头，不能直接视为完整分镜。

重排之后重新检查身份阅读、目标动作与结尾停留；如果改变时间，音效触发点也要跟着更新。允许节拍内动作重叠以提高效率，但阅读静止段必须真实静止。
