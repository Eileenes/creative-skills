# 制作、渲染与验收

仅在实际制作视频／预览或需要技术规格时读取本文件。技能不捆绑 Three.js、浏览器、渲染器、用户资产或上游 Onetake 代码；检查环境后按需使用。没有合适运行条件时明确说明具体缺项及当前可交付物，不能假装已导出成片。

## 资产与工程

- 分离主页数据、角色资产、节拍配置、场景代码与导出脚本；让换渠道或时长无需到处替换账号字符串。
- 使用可用的真实头像、封面与代表内容，记录来源。公开技能和模板不保存任何一次任务的私人素材。源工程只打包本次允许交付的资产，不带缓存、凭证或 `node_modules`。
- 按用户要求选择真实 3D、2.5D 或平面动画；不要以平面头像贴图冒充用户要求的可转动 3D 人物。头像不足以确定的身体、背面和服装属于补充设计，交付时简短说明。
- UI 可用 Canvas 绘制纹理，但把头像、按钮、资料、数字和内容卡拆成能连续运动的层。避免整页瞬间替换。文字使用实际可用的中文字体，渲染前等待字体和图片就绪。
- 在最终镜头角度检查脸、发型、眼镜及关键特征。正面设定图可辨识，不代表低角度或俯视镜头中仍然可辨识。
- 角色接触点使用面板局部坐标或明确的跟随关系，避免面板移动后落脚悬空。检查层级、深度和阴影，防止统计文字被移动的头像／面板遮住。

## 时间与连续性

严格时间驱动版本建议暴露：

```js
window.__ready = assetsReady; // Promise：纹理、模型和字体全部就绪
window.__seek = (t) => {
  const time = Math.max(0, Math.min(duration, t));
  updateSceneFromTime(time);
  renderer.render(scene, camera);
};
window.__meta = {duration, width, height, fps};
```

API 的具体实现由工程决定，但必须保证相同 t 的画面相同。不要用上一帧累计位置、实时墙钟、未固定随机种子或只向前运行的物理状态决定画面。可以预计算固定轨迹或使用从时间解析求值的运动。

纹理缓存也要确定：若用量化键，应从量化值生成纹理，不能拿同一个取整键缓存不同的未取整状态。UI 文本、粒子、后处理和随机噪声同样遵守确定性。

给每个转场标明连续实体，检查边界前后帧：头像是否沿连续路径放大、卡片是否真正展开、角色是否保持空间关系。不要靠快速甩镜掩盖整页硬替换。严格版无硬切；允许剪辑的版本按用户选择执行并准确描述。

## 镜头、运动模糊与静止

- 跟拍可用 `sineInOut`，甩镜可用 `expoInOut`，拉远可用 `expoOut`；这些是可覆盖的默认运动语言，不是所有运动必须套同一曲线。
- 重落地的震动由实际接触时刻触发。震幅和手持晃动不应损害账号与关键资料阅读；静止段全部归零。
- 快速运动使用时间采样或等效的真实运动模糊。可从 180° 快门起步，根据速度调整采样；需要多帧平均时在线性光中合成，之后转换输出色彩空间。一般二维高斯模糊不等价于运动模糊。
- 性能估算应追踪转动的边缘、伸展肢体和文字／面板边缘，不能只依据物体中心速度；中心不动也可能有快速旋转。
- 先测单帧和高运动区渲染成本，估算导出耗时；根据画质调整分辨率之外的采样、并发和纹理成本，不偷偷降低用户规格。
- 某些外部快门工具的硬切保护会把极快连续运动误判为硬切。仅在已经核对整段无硬切时，使用其合适的连续镜头模式；不能为绕过真实断点随意关掉保护。
- 完全静止段冻结镜头、角色、UI、光标、粒子、灯光变化和后处理噪声。声音可按用户要求保留或衰减；静止指视觉完全不动。采样窗口也要避免侵入本应完全静止的内部帧。
- 角色在其出场到离场区间内应完整可见；用户明确设计的入画／离场除外。画幅变化重新调整构图和轨迹，不能把横屏直接裁掉两侧当作竖屏版。

## 可读性

在最终输出像素尺寸检查，不能只在大浏览器窗口看。重要账号、姓名、价值句与 CTA 应在视觉焦点上，有足够字号、对比度、停留时间和无遮挡空间。斜拍的面板要考虑透视压缩；必要时改变角度或局部放大。

长简介可分段或精简为短价值句，不能靠极小字体塞全。保留原文与改写的区别。片尾二维码需要足够稳定和清晰；测试生成／渲染后的码，而不只是源图片。

## 音效

按最终时间轴合成或摆放声音。按钮、脚步和文字落下的声音对准实际接触帧，而非跳跃顶点或动画启动时刻。可按材质使用木头敲击、低频闷响、风声、玻璃音、气泡声等，但不用角色不具备的动作音效。

声音模式可选静音、轻音效、旁白、音乐或混合。默认无背景音乐；用户要求配乐时用可用且来源明确的素材。按用户指定峰值控制，未指定时可采用保守的音效混音目标并记录。检查最终编码音轨峰值，不能只检查中间 WAV；AAC 编码后可能改变峰值。结尾无突兀截断，不能为拖尾改变用户指定总时长。

## 必要验收

| 检查 | 最低证据 |
| --- | --- |
| 资料 | 核对展示名、账号、简介、入口、按钮文字与引用素材；禁止残留其他渠道的账号 |
| 规格 | 检查最终视频时长、分辨率、fps、帧数与音轨；说明帧量化带来的实际差异 |
| 确定性 | 选起点、过渡、运动和静止时间，以不同顺序调用 seek，对相同 t 的输出做比较 |
| 连续性 | 检查每个故事节拍交界的前后画面和连接实体；自动得分只能辅助，不能代替边界检查 |
| 入画 | 对关键动作及高速度区检查角色完整范围，条件允许时逐帧或采样投影边界 |
| 可读性 | 在实际分辨率看姓名、账号、资料及片尾，检查透视与遮挡 |
| 静止 | 逐帧比较指定静止段内部画面；编码成片可另用容差／冻结检测验证，不把轻晃称为静止 |
| 运动模糊 | 查看最高速度动作，确认边缘是沿真实轨迹的模糊，没有明显稀疏重影或误判硬切 |
| 声音 | 确认主要接触事件同步、最终音轨无削波且符合约定峰值、片尾自然结束 |

按实际改动运行必要检查。已通过的检查无需无理由反复扩大。报告真实结果，不写未执行的测试、不用单个自动评分声称所有边界均已通过。

## 交付

视频模式优先交付可直接播放的 MP4；需要透明、无损或其他格式时按需求增加。源工程应能重新预览和导出，注明依赖、入口、资产和运行命令；如果预览页依赖已渲染视频，应一同提供或明确生成顺序。

最终说明只需包含成片、源工程链接、实际规格，以及用户需要知道的补充设计或限制。多版本分别标明平台／账号／画幅。无需输出内部工具日志。
