# 基础元素与可选配置

## 用户开始前需要准备什么

第一次开始一个项目时，展示简短的“已收到／还缺”清单。把以下最低输入解释清楚即可，不要求用户填写所有可选项。

| 类别 | 最低需要 | 有则更好 | 缺失时如何处理 |
| --- | --- | --- | --- |
| 主页 | 平台、展示名、账号或入口、要介绍的内容；链接／截图／文字均可 | 清晰访客视角截图、头像原图、封面、代表作品、资料来源时间 | 先提取现有资料；不能访问链接时说明限制，询问必要内容，不伪造真实主页 |
| 角色 | 参考图／头像／文字描述，或者“不用角色” | 全身与侧背面图、透明图、角色规范、可用 3D 模型、表情参考 | 只有头像仍可制作；提前说明新补充的身体细节。指定沿用某角色却缺参考时，请求必要素材 |
| 行动号召 | 关注／订阅／访问／扫码等目标，以及对应账号或入口 | 确定的片尾文案、二维码原图、希望强调的价值 | 可建议合适动作；真实目的地不凭空猜测。发布视频前须补齐最终入口 |
| 视频规格 | 时长和画幅，或“请按用途推荐” | 发布渠道、像素尺寸、fps、格式、是否循环、截止要求 | 依据用途选一个工作方案并说明；明确参数已有时直接沿用 |

仅有主页链接和头像也可以开始，不强制要求建模文件或完整人物设定表。截图分辨率不足时，可以用真实文字重绘 UI；头像等图片优先用原图，避免把小截图无限放大。网页读不到不等于用户必须提供账号密码。

要展示二维码时，使用用户提供的有效码，或从已确认且适合扫码的目的地生成，并检查能否解码以及实际跳转。不要生成像二维码的装饰纹理，也不要把任意网页链接称为平台原生关注入口。

## 可调整项

这些是选择空间，**不是每次都要问一遍的问卷**。只主动询问真正影响方案而上下文无法判断的少数项。

| 配置 | 选择示例 | 处理原则 |
| --- | --- | --- |
| 交付物 | 制作话术、分镜、预览、成片＋源文件 | 按用户动词和上下文判断 |
| 时长 | 8 秒、19 秒、45 秒、任意正时长 | 可指定整片或单个节拍时长；预算不足时减步骤而非不可读地加速 |
| 画幅与规格 | 16:9、9:16、1:1、自定义尺寸、24／30／60fps | 画幅变化要重新构图；技术上需要偶数像素等限制时明确解释 |
| 角色 | 本人头像人物、猫、鲸鱼、机器人、球体、无角色 | 角色与真实主页头像可不同 |
| 角色材质 | 体素、黏土、毛绒、低多边形、卡通 3D、2.5D | 区分真实 3D 和 2.5D，依用户要求选择 |
| 出场方式 | 从头像跳出、卡片折出、光标组合、从画外走入 | 与角色形态和一镜到底过渡相适应 |
| 操作路径 | 直接主页、搜索、作品进入作者、栏目导览 | 不强制浏览器、Dock 或打字环节 |
| 动作 | 手按、爪拍、碰触、跳跃、滚动、挥手 | 动作先于反馈；保持形态合理 |
| 视觉环境 | 桌面、纸张、展台、微缩世界、纯色空间 | 配色和平台标识可协调，但不篡改真实账号标识 |
| 镜头 | 平稳、低角度跟拍、甩镜、俯视、轻手持 | 兼顾文字阅读和角色完整入画 |
| 连续性 | 严格一镜到底、允许剪辑、循环 | 一镜到底需连续空间／实体关系；剪辑版不声称无硬切 |
| 静止段 | 位置、长度、是否保留 | 严格版预留约 1 秒或更长真实静止；内容多时需要更久 |
| 声音 | 无声、动作音效、旁白、音乐、混合 | 默认轻音效无音乐；用户可覆盖。峰值随交付需求设置 |
| 目标动作 | 关注、订阅、访问作品集、扫码、收藏 | 使用实际平台表达，或明确为宣传概念界面 |
| 片尾 | 账号、价值短句、网址、二维码、平台图标 | 可读且目的地真实；不塞入不相关的所有渠道 |
| 数字演示 | 不变、用户指定模拟增长 | 默认保持来源数字；不能暗示动画完成了真实关注 |

## 信息记录

使用 `assets/brief.template.json` 时，由代理填写，不要求用户编写 JSON。

- `profile.bio_original` 保存真实原文；`value_proposition` 保存拟定的短文案，不能把精简文案说成原文。
- `profile.sources` 记录来源文件／URL、对应字段与获取时间，按可用证据填写。
- `mascot.identity_invariants` 记录发型、眼镜、服装等要保留的特征；`newly_designed_details` 记录参考中没有的新设计。
- `assumptions` 记录代理做出的工作假设；`missing_required_inputs` 只列阻止正确交付的缺项。
- `beats` 可由叙事阶段填写，空数组不代表一个可渲染的计划。输出参数也必须补齐后再交给渲染器。
- 不把真实个人资料写回技能模板，不把用户资产打包进公共技能。

## 简短询问示例

已知账号、头像和目标时：“主页资料和角色参考都已收到。时长和画幅可以自定；如果没有偏好，我按 20 秒竖屏安排，并保留片尾阅读停顿。”随后推进不依赖答复的整理工作。对必须提供的真实账号或指定素材，保持缺项待补，不能把未回复当作授权或素材。

## 调用示例

### 小红书，短竖屏，猫咪

“用 $profile-promo 做 15 秒竖屏小红书求关注视频。这是我的主页截图和账号，吉祥物用这只毛绒猫；它从头像旁走出来，用爪子拍关注。不要 Dock，保留轻音效，片尾至少停 1.5 秒。头像仍用我的原头像。”

### YouTube，较长解说，已有模型

“用 $profile-promo 做 35 秒、1920×1080、60fps 的频道介绍。吉祥物用附件里的机器人 GLB，介绍我的两类代表内容，结尾引导订阅。配英文旁白，镜头平稳。频道链接和文案在这里。”

### 个人网站，只交话术，无角色

“用 $profile-promo 把我的作品集主页整理成 12 秒方形动画的完整制作话术。不要吉祥物，用光标和卡片展开串联，结尾展示访问网址。暂时不要制作视频。”

### 同一 IP，多渠道独立成片

“用 $profile-promo 沿用同一个人物，分别做 X 的 18 秒横屏版和 B 站的 25 秒竖屏版。这里是两个主页的资料；各自使用真实页面结构和账号，片尾动作按各平台表达。”

以上示例表达配置方式，不是对这些平台当前 UI 的固定描述。实际制作仍以本次可核对资料为准。
