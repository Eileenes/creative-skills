# 主页宣传动画

把“我是谁、我提供什么价值、观众下一步做什么”组织成可看懂、可记住的主页宣传动画。角色的动作触发界面反馈，前一个画面为后一个画面提供连续的过渡。角色可以是人物、动物、物品或抽象形象，也可以不用角色。

## 先明确交付物与基础元素

从用户本轮及已有上下文判断交付物：完整制作话术、分镜／预览、可播放视频，或多渠道版本。用户说“做视频”时完成视频与必要验证，不能只交脚本；用户只要话术时不擅自开始耗时渲染。

**每个新项目开始时，必须明确告知用户需要以下四类基础输入，并说明哪些已收到、哪些还缺。先读取提供的截图、文字和链接，避免让用户重复填写。**

| 基础元素 | 最低可用输入 |
| --- | --- |
| 主页资料 | 平台名，以及主页链接、清晰截图或完整文字资料之一；至少能确认展示名、账号标识和介绍内容 |
| 吉祥物／角色 | 头像、参考图、已有 IP／模型，或文字设定；也可以明确不用角色。完整人物图和 3D 模型不是必需条件 |
| 目标动作 | 希望观众关注、订阅、访问、扫码还是了解作品；提供对应账号或目标入口 |
| 视频规格 | 希望的时长与横屏／竖屏／方形；也可让代理推荐。分辨率、帧率及其他偏好均可选填 |

可用开场：“需要准备主页资料、角色素材或设定、希望观众完成的动作，以及时长和画幅。你已经提供了……；还缺……。其余我可以按渠道推荐。”这是一份输入说明，不是要求用户重新确认所有内容。

用户可直接说自然语言，不要求填写表单。代理可用 [brief.template.json](assets/brief.template.json) 记录需求；其中 `null` 和空数组是待填项，不是假定值。完整准备清单、可选项及调用示例见 [inputs-and-options.md](references/inputs-and-options.md)。

只有会阻止正确制作的缺项才提问，例如无法确定要宣传的账号，或指定角色却没有可用参考。可独立推进的工作继续进行。对一般风格和节奏自行采用合理默认值，并说明假设；不得把缺失的真实资料编造出来。不要把素材说明变成逐阶段批准流程。

## 配置原则

- **用户当前选择优先。** 时长、平台、画幅、帧率、角色、入口、交互、场景、镜头、音效、配乐、旁白、结尾和交付格式都可变。已有明确选择不重复询问。
- 不固定为 19 秒、横屏、深蓝桌面、体素、Dock、搜索路径或“落地=点击”。不把某次案例的人名、账号、统计数字或资产作为后续默认内容。
- 账号头像与动画角色是两个独立选项。用户用猫当吉祥物时，真实主页头像仍按资料保留；只有用户要求时才让人物从头像里出现。
- 时长与画幅未指定时，结合用途提出一个建议；用户已让代理决定时直接采用。完全缺少用途线索时可声明以 20 秒、1280×720、30fps 作为工作假设，这不是范围限制。
- 默认连续镜头、轻量动作音效、无配乐；这些可以覆盖。严格一镜到底版本应有真实的静止阅读段，通常约 1 秒或更长，按内容调整。用户要求持续运动或剪辑版时遵从，并明确不再称其为严格 Onetake 版本。
- 粉丝／订阅数变化默认关闭；仅在用户明确要求时作为动画演示。不能声称真实账号因此增长。

## 执行流程

### 1. 整理事实与角色

记录资料来源，区分“用户提供的截图”“当前网页可见内容”“用户指定的演示效果”。平台页面可能需要登录或存在访客／本人视角差异；读取受限时使用已提供资料，不因无法抓取而编造界面与统计数。截图与网页冲突时按用户指定来源；未指定且影响内容时简短澄清。

确定角色不变特征、体型和动作语言。复用用户已有角色规范；有适用的专用 IP 技能时读取。仅有头像可据此设计身体，但要区分保留的特征与新补充的服装／身体细节。需要生成或编辑位图时使用可用的图像技能；不把图像生成作为所有任务的强制依赖。

### 2. 按目标设计连续叙事

优先采用用户已选方案。按实际平台选择“直接进入主页”“搜索账号”“从作品进入作者主页”等路径，删除无助于目标的中间操作。不要把平台 A 的导航、认证标记或按钮文字套到平台 B。

为每一拍写明：时间／帧区间、要传达的信息、角色动作、界面反馈、镜头、读字或静止时间、音效，以及连接下一拍的实体。动作要有因果关系：接触后产生反馈，界面变化后角色再响应。人物可以手按，猫可以拍爪，机器人可以吸附；无需全部跳跃、打字或喷水。

先给关键信息阅读与目标动作留时间，再分配出场、游走和装饰。短片减少步骤，长片增加有价值的内容；不要简单把同一套 19 秒动作整体加速或减速。规则及节拍分配工具见 [story-and-platforms.md](references/story-and-platforms.md)。

连续版本的每次变化都应保留可追踪实体，例如头像、卡片、按钮或角色；用它的移动、展开、变形带出下一阶段。单纯用透明度替换两张整页贴图不算完成连续过渡。阅读停顿期间角色、镜头、UI、粒子、光标及后处理全部冻结。

### 3. 制作与检查

制作话术模式：输出可直接复制的完整需求，包含用户已选参数、真实资料、角色设定、节拍、镜头、声音和验收条件；清楚标记尚缺素材与可选分支。

视频模式：继续实现、渲染和验证。默认可用 Three.js；沿用用户指定的引擎或现有项目。要求 3D 时使用实际三维角色与空间，不能以始终朝向镜头的平面人像冒充。先检查关键静帧中的角色辨识、主页可读性和镜头构图，修正后继续，不强制等待批准。

严格按时间驱动的版本提供 `window.__seek(t)`；同一时间在任意跳转顺序下得到同一帧。快速运动使用真实的时间多重采样运动模糊或等效实现；静止段关闭时间噪声。详细实现、音画同步和验收清单见 [production-and-qa.md](references/production-and-qa.md)。

用户明确要求遵循 Onetake 时，读取本地可用版本或 [Onetake SKILL.md](https://github.com/feitangyuan/onetake/blob/main/SKILL.md)，结合本次需求应用；其默认时长、画幅和方案数量不得覆盖用户已给出的选择。需要其渲染工具时再获取，遵守相应许可。本技能不捆绑上游代码，也不要求每个项目预先安装 Onetake。

### 4. 交付与复用

按所需交付成片、可编辑源工程与资产清单；只要话术则交付话术。简要报告实际规格、已验证项目、素材补充设计和仍存在的限制。不以“有源码”代替用户要求的成片，不把未渲染或未检查的结果描述为完成。

多渠道任务复用角色、视觉语言和合适的动作，但分别核对平台资料、目标入口、界面结构与阅读节奏。仅在用户要求时生成多个版本或拼接跨平台长片。复用时避免带入上一个账号的资料与资产。

本技能只制作宣传内容与模拟界面操作；不实际关注、订阅、登录或发布到账号。
